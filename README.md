# 🎫 Session Tickets Bot (v3.3)

Telegram-бот для организации командной подготовки экзаменационных билетов в вузе. Автоматизирует регистрацию участников, распределение вопросов, сдачу решений, модерацию редакторами и двустороннюю синхронизацию ведомостей с Google Sheets.

## ✨ Основные возможности

### Жизненный цикл сессии (5 этапов)
1. **PREPARATION (Подготовка):** настройка дедлайнов этапов и первичный импорт дисциплин/билетов из Google Sheets.
2. **REGISTRATION (Регистрация):** регистрация студентов по ФИО, выбор предметов для подготовки и подача заявок на роль редактора.
3. **DISTRIBUTION (Распределение):** автоматическая нарезка билетов между студентами («змейкой») и редакторами с выгрузкой в Google Таблицы, ручная корректировка ведомостей.
4. **TICKETING (Подготовка и проверка):** сдача файлов решений студентами (с проверкой белого списка расширений), проверка и отправка на доработку редакторами, цветовая индикация статусов в Google Sheets.
5. **FINISHED (Завершение):** закрытие приёма новых файлов, итоговая выгрузка одобренных билетов.

### Ролевая модель
- **Студент (`/user`, `/start`):** выбор предметов, просмотр списка своих вопросов с зацикленной пагинацией, загрузка решений с комментариями, отслеживание статусов (`⚪/🟡/🔴/🟢`) и замечаний редактора, отправка обратной связи.
- **Редактор (`/editor`):** очередь проверки билетов с приоритетом непроверенных, просмотр документа и комментария студента в одном сообщении, принятие, отправка на доработку с замечанием, замена файла, отправка обратной связи.
- **Главный редактор / Админ (`/admin`):** управление дедлайнами и этапами, утверждение редакторов, двусторонняя синхронизация с Google Sheets, статистика прогресса, массовые рассылки по гибким фильтрам с прикреплением до 10 документов, выгрузка готовых файлов по предметам (альбомом или единым ZIP-архивом), ручное добавление участников, выгрузка журнала обратной связи (`feedback.md`).

## 🛠 Стек технологий

- **Runtime & Language:** Node.js, TypeScript (ES2022 / NodeNext)
- **Telegram Framework:** [grammY](https://grammy.dev) + `@grammyjs/files`
- **Database:** SQLite (`better-sqlite3`) + Type-Safe Query Builder [Kysely](https://kysely.dev)
- **Integrations:** Google Sheets API v4 (`googleapis`)
- **Utilities:** `archiver` (сборка ZIP-архивов)
- **Architecture:** Layered Architecture (Repositories → Services → Managers → Screen State Machine)

## 🚀 Установка и запуск

### 1. Клонирование и установка зависимостей
```bash
git clone https://github.com/Ladno1907/session-tickets-bot.git
cd session-tickets-bot
npm install
```

### 2. Настройка окружения
Создайте файл `.env` в корне проекта:
```env
BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
SPREADSHEET_ID=1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms
CREDENTIALS_PATH=./credentials.json
DB_PATH=./storage.db
CHIEF_EDITOR_IDS=123456789,987654321
ALLOWED_EXTENSIONS=.pdf,.docx,.doc,.md,.txt,.tex
```
* `ALLOWED_EXTENSIONS` — необязательный параметр (по умолчанию `.pdf,.docx,.doc,.md,.txt,.tex`).  
Поместите JSON-ключ сервисного аккаунта Google Cloud в `CREDENTIALS_PATH` и выдайте ему права **Редактора** на вашу Google Таблицу.

### 3. Структура листа в Google Sheets
Каждый предмет должен находиться на отдельном листе, название которого совпадает с названием предмета. Таблица начинается с **8-й строки**:
- **Колонка A:** Номер билета (`1, 2, 3...`)
- **Колонка B:** Текст вопроса
- **Колонка C:** ФИО студента (окрашивается ботом в цвет статуса)
- **Колонка D:** ФИО редактора (смежные ячейки объединяются автоматически)

### 4. Команды запуска
```bash
# Запуск в режиме разработки (tsx)
npm run dev

# Сборка TypeScript и запуск в продакшене
npm run build
npm start

# Утилиты для работы с БД
npm run db:inspect   # Просмотр текущего состояния таблиц в консоли
npm run db:seed      # Заполнение БД тестовыми пользователями
```

## 📂 Структура проекта

```text
src/
├── bot.ts                    # Точка входа, middleware, роутинг команд и экранов
├── config.ts                 # Валидация и загрузка .env
├── database/
│   ├── adapters/             # Адаптер сессий grammY для SQLite
│   ├── repositories/         # Репозитории таблиц и Read-Only Views (Kysely)
│   ├── sheetRepositories/    # Интеграция с Google Sheets API
│   ├── client.ts             # Инициализация SQLite + CamelCasePlugin
│   ├── migrate.ts            # Идемпотентные миграции схемы БД
│   ├── inspect.ts            # CLI-инспектор базы данных
│   └── seed.ts               # Генератор тестовых данных
├── managers/
│   ├── MessageManager.ts     # Single-Window UI и массовые рассылки (текст и медиагруппы)
│   └── StageManager.ts       # Конечный автомат этапов и триггеры дедлайнов
├── screens/
│   ├── admin/                # Экраны панели администратора по всем этапам
│   ├── editor/               # Экраны очереди и проверки билетов редактором
│   ├── student/              # Экраны регистрации и сдачи билетов студентом
│   ├── base.screen.ts        # Контракт экрана (BaseScreen / RenderResult)
│   ├── feedback.screen.ts    # Универсальный экран обратной связи и баг-репортов
│   ├── pagination.ts         # Зацикленный пагинатор списков и кнопок
│   └── screenFactory.ts      # Реестр и фабрика экранов
├── services/                 # Бизнес-логика (ChiefEditor, Distribution, Editor, Student)
├── storage/                  # Локальное версионируемое хранилище файлов, ZIP-архивов и feedback.md
├── types/                    # Типы контекста, сущностей и схемы БД
└── utils/                    # Утилиты форматирования и экранирования Markdown
```
